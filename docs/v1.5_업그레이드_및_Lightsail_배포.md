# MT옵틱스 v1.5 업그레이드 및 Lightsail 반영

현재 구성 기준:

```text
GitHub: https://github.com/YOUR_ACCOUNT/mt-optics-system
Lightsail 소스: /var/www/mt-optics
Static IP: YOUR_STATIC_IP
권장 운영주소: https://order.mtoptics.net
PM2 이름: mt-optics
MySQL DB: mt_optics / 로컬 127.0.0.1:3306
```

## 1. 반영 기능

- Kakao 우편번호 서비스로 도로명주소(신주소)·지번주소(구주소) 검색 및 선택 등록
- 엑셀 대상 파일명을 화면에 명시: `거래처 정보.xls`, `판매처 원장 상세.xls`, `일별영업현황.xls`
- 기존 양식 별칭 지원, 업로드 전 분석, 업로드 후 보완 검토목록
- 휴대폰용 `모바일 영업` 화면과 하단 메뉴
- 주문·수금 수정 및 사유 필수 논리삭제
- 수정·삭제 전후 값, 사용자, 접속 IP, 브라우저, 처리시각 감사기록
- 로그인/API 요청 제한, 보안 헤더, 업로드 용량·확장자·시그니처 제한
- 운영 보안 사전점검, 자동 DB 백업, 롤백 스크립트

## 2. 배포 전에 먼저 해야 할 보안조치

### GitHub

1. 저장소 `Settings → General → Change repository visibility`에서 **Private**로 변경합니다.
2. `Settings → Pages`에서 GitHub Pages를 비활성화합니다.
3. 기존 Netlify 사이트가 이 저장소와 연결되어 있으면 Netlify에서 연결을 해제합니다.
4. 실제 고객 엑셀과 `.env`가 저장소에 없는지 확인합니다.

### 비밀번호

대화와 화면에 노출된 기존 MySQL·관리자 비밀번호는 새 값으로 변경합니다. DB 사용자 비밀번호 변경 예시:

```bash
sudo mysql
```

```sql
ALTER USER 'mtopt'@'localhost' IDENTIFIED BY '새로운_강한_DB비밀번호';
FLUSH PRIVILEGES;
EXIT;
```

## 3. PC의 GitHub 저장소에 v1.5 덮어쓰기

1. 실행 중인 로컬 프로그램을 종료합니다.
2. 제공된 v1.5 전체 ZIP을 별도 폴더에 풉니다.
3. ZIP 안의 파일과 폴더를 현재 GitHub 로컬 저장소 루트에 덮어씁니다.
4. 다음 이전 파일은 삭제합니다.

```text
netlify/
netlify.toml
package-lock.json
node_modules/
```

실제 고객자료는 로컬에 보관해도 되지만 Git에는 포함하지 않습니다.

Windows PowerShell에서 저장소 루트로 이동한 뒤 자동 정리:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\prepare-github-update.ps1
```

변경 확인 및 업로드:

```powershell
git status
git add -A
git commit -m "MT Optics v1.5 security mobile address excel audit"
git push origin main
```

GitHub 화면에서 `.env`, `node_modules`, 실제 `.xls/.xlsx`가 올라가지 않았는지 확인합니다.


### Private 저장소로 바꾼 뒤 Lightsail 읽기 권한 연결

저장소를 Private로 변경하면 기존 공개 HTTPS 주소의 `git fetch`가 인증 없이 동작하지 않습니다. 비밀번호나 개인 토큰을 서버 파일에 저장하지 말고 **읽기 전용 Deploy key**를 사용합니다.

Lightsail SSH에서 최초 1회:

```bash
ssh-keygen -t ed25519 -C "mtoptics-lightsail" -f /home/ubuntu/.ssh/id_ed25519 -N ""
cat /home/ubuntu/.ssh/id_ed25519.pub
```

출력된 `ssh-ed25519 ...` 한 줄 전체를 복사한 뒤 GitHub에서:

```text
저장소 Settings → Deploy keys → Add deploy key
Title: mtoptics-lightsail-readonly
Key: 복사한 공개키
Allow write access: 체크하지 않음
```

다시 Lightsail SSH에서:

```bash
ssh-keyscan -H github.com >> /home/ubuntu/.ssh/known_hosts
chmod 700 /home/ubuntu/.ssh
chmod 600 /home/ubuntu/.ssh/id_ed25519 /home/ubuntu/.ssh/known_hosts
cd /var/www/mt-optics
git remote set-url origin git@github.com:YOUR_ACCOUNT/mt-optics-system.git
ssh -T git@github.com
```

`successfully authenticated`와 읽기 전용 안내가 나오면 정상입니다. 이후 `git fetch origin main`과 자동 갱신 스크립트를 사용할 수 있습니다.

## 4. Lightsail `.env`를 먼저 수정

새 버전은 운영 보안 사전점검을 통과해야 재시작됩니다. 서버에서:

```bash
cd /var/www/mt-optics
nano .env
```

권장값:

```env
PORT=3000
NODE_ENV=production
JWT_SECRET=여기에_32자_이상_무작위값
JWT_EXPIRES_IN=8h
CORS_ORIGIN=https://order.mtoptics.net

DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=mtopt
DB_PASSWORD=새로운_강한_DB비밀번호
DB_NAME=mt_optics
DB_CONNECTION_LIMIT=10
DB_SSL=false
DB_AUTO_CREATE_DATABASE=false
AUTO_MIGRATE=true

ADMIN_USERNAME=admin
ADMIN_PASSWORD=새로운_관리자_로그인비밀번호
ADMIN_FULL_NAME=시스템관리자
ADMIN_EMAIL=admin@mtoptics.local
SEED_SAMPLE_DATA=false

ALLOW_REMOTE_SHUTDOWN=false
SECURITY_STRICT_MODE=true
TRUST_PROXY=1
LOGIN_RATE_LIMIT_PER_15M=20
API_RATE_LIMIT_PER_15M=1200
MAX_EXCEL_FILE_MB=20
```

저장 후:

```bash
chmod 600 .env
```

**현재 IP 주소로만 임시 테스트하고 HTTPS 도메인이 아직 없을 때**는 `SECURITY_STRICT_MODE=false`로 잠시 테스트할 수 있습니다. 실제 사용자 테스트 전에는 `order.mtoptics.net` HTTPS와 Cloudflare Access를 구성하고 다시 `true`로 바꿉니다.

관리자 계정이 이미 DB에 만들어진 뒤 `.env`의 `ADMIN_PASSWORD`만 바꾸면 기존 로그인 비밀번호는 자동으로 바뀌지 않습니다. 사용자관리 화면에서 변경하거나 bcrypt 해시 재설정이 필요합니다.

## 5. 엑셀 처리 모듈 보안 업데이트

v1.5는 오래된 npm 레지스트리의 `xlsx 0.18.5` 대신 SheetJS 공식 배포본 `0.20.3`을 직접 설치하도록 고정했습니다. 배포 시 `npm install`이 SheetJS 공식 CDN에 접속할 수 있어야 합니다.

## 6. 백업 계정파일 최초 1회 설정

```bash
nano /home/ubuntu/.my.cnf
```

```ini
[client]
user=mtopt
password=새로운_강한_DB비밀번호
host=127.0.0.1
```

```bash
chmod 600 /home/ubuntu/.my.cnf
mkdir -p /home/ubuntu/backups/mt-optics
```

## 7. Lightsail 자동 갱신

GitHub 업로드가 끝난 뒤 SSH에서:

```bash
cd /var/www/mt-optics
chmod +x deploy/*.sh
./deploy/update-lightsail.sh
```

처리 순서:

```text
DB 백업 → GitHub 최신 소스 → 보안 사전점검 → 패키지 설치 →
문법검사 → DB 자동 마이그레이션/PM2 재시작 → Nginx 검사 → 헬스체크
```

보안 사전점검 또는 문법검사에서 실패하면 기존 PM2 앱은 계속 실행됩니다.

## 8. 수동 갱신이 필요한 경우

```bash
cd /var/www/mt-optics
git fetch origin main
git reset --hard origin/main
node deploy/preflight.js
npm install --omit=dev --no-package-lock --no-audit --no-fund
npm run check
pm2 restart mt-optics --update-env
pm2 save
sudo nginx -t
sudo systemctl reload nginx
curl http://127.0.0.1:3000/api/health
```

## 10. 엑셀 등록 순서

```text
1. 엑셀가져오기
2. 거래처 정보.xls 선택
3. 파일 분석
4. 경고 확인 후 DB 등록
5. 판매처 원장 상세.xls 분석/등록
6. 일별영업현황.xls 분석/등록
7. 보완 검토목록 확인
```

정확한 새 3개 파일이 현재 검토본과 열 구성이 다르면 `파일 분석` 화면의 판별유형과 누락경고를 우선 확인합니다.

## 11. 문제 발생 시 롤백

배포 스크립트 마지막에 출력된 이전 커밋 ID를 사용합니다.

```bash
cd /var/www/mt-optics
./deploy/rollback-lightsail.sh 이전커밋ID
```

DB 구조변경 전 백업파일은 `/home/ubuntu/backups/mt-optics`에 보관됩니다.

## 12. 자동백업

```bash
crontab -e
```

매일 새벽 2시:

```text
0 2 * * * /var/www/mt-optics/deploy/backup-db.sh >> /home/ubuntu/backups/backup.log 2>&1
```
